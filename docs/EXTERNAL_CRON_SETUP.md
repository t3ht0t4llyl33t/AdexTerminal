# Внешний бесплатный крон для aDex

Vercel Hobby не гарантирует минутные расписания, поэтому фоновые задачи уводим на бесплатный внешний cron-сервис. У бесплатных кронов (например cron-job.org) жёсткий 30-секундный таймаут на один запрос, поэтому у нас **два эндпоинта** — быстрый и дневной. Оба авторизуются одним и тем же `CRON_SECRET` через `Authorization: Bearer …`.

- `/api/cron/tick` — каждые 5 минут. Обновление Radar-кэша, проверка алертов, Lightning Boost. Все три подзадачи запускаются параллельно и укладываются в 10–15 секунд.
- `/api/cron/daily` — раз в сутки. Курс TON, дневной снимок метрик, проверка подписок, отправка дайджеста. Все идут по очереди, идемпотентно (`skipped`, если сегодня уже отработало).

---

## 1. Что должно быть в переменных окружения Vercel

Проверьте в Vercel → Project → Settings → Environment Variables (обязательно в **Production**):

- `CRON_SECRET` — любая длинная случайная строка (32+ символа). Секрет знают только Vercel и внешний cron.
- `TONAPI_KEY` — уже есть у вас.
- Всё остальное — как раньше (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `TELEGRAM_BOT_TOKEN` и т. д.).

Если `CRON_SECRET` только что добавили — сделайте **Redeploy** последнего продакшн-деплоя, иначе переменная не подхватится.

## 2. Регистрация на cron-job.org

Заведите бесплатный аккаунт на https://cron-job.org/ (подтверждение по email). Cronjobs → Create cronjob. Дальше создаём **два** задания.

## 3. Задание №1 — «aDex tick» (каждые 5 минут)

| Поле | Значение |
|---|---|
| **Title** | `aDex tick` |
| **URL** | `https://ВАШ-ДОМЕН/api/cron/tick` (продакшн, не превью) |
| **Schedule** | Every 5 minutes (`*/5 * * * *`) |
| **Time zone** | UTC (для интервального крона не важно, но лучше единообразно) |
| **Request method** | GET |
| **Timeout** | 30 seconds (максимум бесплатного плана) |
| **Save responses in job history** | ON (хотя бы на первые дни) |
| **Notify me when execution fails** | ON |

Advanced → Request headers, добавить один заголовок:

| Header name | Value |
|---|---|
| `Authorization` | `Bearer ВАШ_CRON_SECRET_ИЗ_VERCEL` |

Значение — та же строка, что в `CRON_SECRET` в Vercel, символ в символ, без кавычек. Слово `Bearer` живёт только в этом поле Value, перед секретом, через один пробел. В Vercel в переменную кладётся только сам секрет, без `Bearer`.

Сохранить.

## 4. Задание №2 — «aDex daily» (раз в сутки)

| Поле | Значение |
|---|---|
| **Title** | `aDex daily` |
| **URL** | `https://ВАШ-ДОМЕН/api/cron/daily` |
| **Schedule** | Custom → `20 0 * * *` (каждый день в 00:20) |
| **Time zone** | **UTC** — критично, иначе снимок метрик уедет по дате |
| **Request method** | GET |
| **Timeout** | 30 seconds |
| **Save responses in job history** | ON |
| **Notify me when execution fails** | ON |

Advanced → Request headers, тот же самый заголовок:

| Header name | Value |
|---|---|
| `Authorization` | `Bearer ВАШ_CRON_SECRET_ИЗ_VERCEL` |

Сохранить.

## 5. Проверка

- В cron-job.org → задание → **TEST RUN**: должен ответить `HTTP 200`. Если `401` — не совпадает `CRON_SECRET`. Если `500` — раскройте тело ответа, там JSON с полем `subtasks.<имя>.error`.
- В базе (Supabase → Table Editor → `cron_runs`) должны появляться строки: у тика — со статусом `ok` каждые 5 минут, у daily — раз в сутки после 00:20 UTC.
- На странице `/status` в приложении видно тот же журнал (последние прогоны + время последней успешной задачи).
- Radar в приложении подтянет свежие данные в течение 5–10 минут после первого успешного тика.

## 6. Что делать при проблемах

- **401 Unauthorized** — не совпадает `CRON_SECRET`. Сверьте копию в Vercel и в cron-job.org (после слова `Bearer ` должна быть **точно та же** строка, что стоит в переменной Vercel), после правки — Redeploy.
- **Timeout** на тике — не должно случиться, тик рассчитан на ≤15 сек. Если стабильно валится по таймауту, проверьте `subtasks.radar-refresh.error` в теле ответа: чаще всего это лимит CoinGecko/GeckoTerminal, разовое и само пройдёт.
- **429 в теле подзадачи** — сторонний API рейт-лимит, разовое, само пройдёт с следующим тиком.
- **Job auto-disabled** — cron-job.org отключает задание после серии подряд идущих ошибок. Разберитесь с причиной (лог в самом задании), снова включите тумблер Enable.
- **Резерв**: опционально можно завести второй аккаунт cron-job.org на те же URL с интервалом со сдвигом (например, `1-56/5 * * * *` — на минуту позже). Тик и daily оба идемпотентны — параллельные запуски отдают `skipped`.

---

Vercel Cron из `vercel.json` больше не используется (`crons: []`). Всё управляется извне двумя заданиями: `tick` каждые 5 минут и `daily` раз в сутки.
